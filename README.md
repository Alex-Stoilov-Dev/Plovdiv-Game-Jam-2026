# Няколко основни команди за GIT, които ще ползваме доста често:

```git
git init
git config --global user.email "вашият-емайл"
git config --global user.name "вашето име"
git clone https://github.com/Alex-Stoilov-Dev/Plovdiv-Game-Jam-2026.git

git add .
git status
git commit -m "вашето съобщение"

git remote add origin https://github.com/Alex-Stoilov-Dev/Plovdiv-Game-Jam-2026.git

git push -u origin <branch>
git push 
git pull 

git branch
git switch -c <new_branch>
git switch <existing_branch>
```

Освен списъка с команди, ще е важно да знаем всяка една какво прави. 

Тези команди ще ги пускаме локално на нашите си компютри. Трябва всички да си свалим GIT, което става супер лесно. GIT на windows идва с една конзола, която ще ползваме (с цел да избегнем гадната Microsoft конзола).

3.  Клониране на съществуващи хранилища и как да правим промени към тях.

Като за начало, всички ще си клонираме работното хранилище:	
```
git clone https://github.com/Alex-Stoilov-Dev/Plovdiv-Game-Jam-2026.git
```
	
Гит може да по иска да напишете името си и паролата в терминала. Ако искате алтернативен начин, можете да си добавите и SSH key към гитхъб. Много е удобно, но може да усложни нагласянето. Ще го обясня накратко по-късно

Когато направите каквито и да е промени в един файл, който е в git хранилище (git repository/repo), тези промени не се запазват веднага. За да направите промените действителни изполвате следните комманди:

``` 
git add .
git commit -m "Вашето съобщение"
```
Командата ``git add .`` ще добави всички промени файлове към "staging" това е просто статус, означава, че сме си свършили промените по файловете и е време те да станат действителни. За да ги направите действителни ползвате втората команда ``git commit -m ""`` . Силно препоръчвам преди ``git commit`` да пускате командата ``git status`` за да видите който файлове ще бъдат променени и тнт. Хубава практика е и може да ни спести време ако случайно commit-нем файл, който не искаме да е commit-нат всъщност.

>Бележка: може да ползвате ``git add *``, но това ще добави абсолютно всички файлове в папката. Много, често има скрити файлове (със точка пред името ".моят-супер-важен-файл.txt), които не искаме изобщо да се следят от git. Ако ползвате ``git add .`` такъв проблем не може да се  имате. 

4. Изпращайки тези промени към GitHub (сайта)
В крайна сметка, идеята е тези промени от локално да отидат към сайта. За да ги изпрати, първо трябва да се подсигурим, че всчиките важни промени са направени. С други думи, пуснали сме ``git add .`` ,``git status`` и ``git commit -m ""``. След това, ще ползвате следната команда:

```
git push -u origin <branch>
```
Тази команда, ще изпрати локалните файлове към GitHub-а ни. Ако случайно Ви излезе грешка пуснете точно тази команда:

```
git remote add origin https://github.com/Alex-Stoilov-Dev/Plovdiv-Game-Jam-2026.git
```

Не би трябвало да Ви се налага, но за всеки случай. След като пуснете:

```
git push -u origin <branch>
```
За първи път, после може да пускате следната команда:
```
git push origin <branch>
```
Тук доста често използвам "<Нещо си>". Това значи, да заменитеи <нещо си> със действително име на branch. Ако погледнете скрийншота горе, ако искаме да изпратим клона super към GitHub пише:

```
git push origin super
```
Ако Ви излезе грешка от сорта на "Remote Branch is ahead by X commits", следвайте тези стъпки:

```
git switch -c <new_branch>
git branch (подсигурете се, че сте на новия клон)
git pull (така, ще свалите първо промените от github)
git merge <клонът-на-който-са-вашите-промени>
git push
```

Това се прави защото в противен случай ``git pull`` може да изтрие вашите промени. С този подход, вие си правите нов клон (може да се казва както искате, стига да не е име на съществуващ клон) в който сваляте действителните промени. След това го смесвате с вашият клон където има промени. Накрая си пускате ``git push``, за да изпратите промените към GitHub 

5. Gitignore файл
``.gitignore`` e текстов файл в основната папка на проекта, който казва на Git кои файлове и папки да не качва в GitHub.

В него изброяваме неща, които не са ни нужни в общото хранилище:

- Временни файлове (които енджинът създава сам, докато работите).
    
- Локални настройки (които са само за вашия компютър).
    
- Големи папки с кеш (които само ще забавят `push` и `pull`).

Това спестява време и място, като държи в GitHub само истинския код и ресурси на играта, а не "боклука", който се генерира при всяко пускане. Това е информативно, просто ще ползваме дефаултен който съм намерил в нета.

6. Как да си нагласите SSH KEY за github ако искате.
	1.  Първото нещо е да отидет във Git Bash (конзоалта, която ще ползвате за гит и без това) и да пуснете тази команда
		```shell 
		ssh-keygen -t ed25519 -C "your_email@example.com
		```
		Може да видите промпт за "Passphrase" това един вид парола. Не е задължително да си правите парола. Ако искате може просто да натиснете ентер и всичко ще е окей. Или напишете парола, която помните. След това ще пуснете следната команда:
		```shell
		cat ~/.ssh/id_ed25519.pub
		```
